# The synthesis and remix sets, 2026-10-05

`content/tiers.json` is the fifth data stage (`tools/tiers.py`). It runs after curation, pins
its input (the curated publication) and its output like the earlier stages, and adds whole
records without changing any existing one. Result: **1,082 activities / 640 sources** in both
tools. The 779 licensed adaptations are untouched.

| | Activities | Provenance class | Label on every record |
|---|---|---|---|
| Licensed collection | 779 | Licensed Adaptation | none (as before) |
| Synthesis set | 211 | 96 Hybrid Synthesis, 112 Original Synthesis, 3 Licensed Adaptation | "Synthesis set · not yet tried" |
| Remix set | 92 | Hybrid Synthesis | "Remix set · not yet tried" |

Both sets were written for the collection in October 2026 and have not been taught or tried.

## 1. What was added, and what was held

Only records with no open review question were added. **77 are held** in the manifest with
their reasons and never reach either tool:

- **18 remix records** flagged for a person to check: consent, data-protection or ethics
  approval (9); a CC BY-SA parent, which needs a record-level CC BY-SA 4.0 notice that the
  collection's CC BY-NC-SA 4.0 license does not satisfy (5); a source license with no
  version (5); a source read only in part (1). Two records carry two reasons.
- **51 synthesis records** flagged for human review in the synthesis workbook.
- **8 synthesis records** not flagged there but adapting a CC BY-SA source with no
  NonCommercial term (WIA-S-HEA-B-01, HEA-B-02, STE-A-12, STE-A-14, STE-B-01, STE-B-05,
  CRO-A-13, CRO-A-14). They are held for the same ShareAlike reason as the five remix records.

## 2. How the sets stay distinct

- **`tier`** (`synthesis` or `remix`) on every set record; the licensed collection has none.
  Top-level `tiers` in `acts.json` and `register.json` give each set's name and description.
- **Provenance classes.** Hybrid Synthesis and Original Synthesis return to `origin`, with
  faculty-facing descriptions, beside Licensed Adaptation. `source_uncertain` stays retired.
  The page test now requires that the synthesis classes appear only on set records.
- **Cards** show an **Origin** fact ("Remix set · not yet tried"). **Activity details** add a
  "Written for this collection, not yet tried" note under *Before you use it*; the set's
  description, every source (all scholarly citations), the attribution for each adapted
  source, *How it was put together*, and, for a remix, **Builds on** with a link to the
  published activity it adapts. *How people and the AI tool divide the work* adds *What it
  depends on the AI tool for* and *What the output is checked against*.
- **The Register** adds a **Where it comes from** filter (published activities, synthesis
  set, remix set; `#activities?set=remix`) and lists both sets in *Where the activities come
  from*. The *How the collection was assembled* step names the two sets.
- **Result order.** Set records carry quality tier `gr: 0`, and `matching.js` counts them as
  having no reported use, like `use: "unreported"`. At an equal match score they follow
  activities whose sources report running them. Match score still comes first, so a set
  record that fits a reader's answers better ranks higher. The stage refuses any other `gr`.

## 3. Field mapping

| Public field | Remix record | Synthesis record |
|---|---|---|
| `t`, `sum`, `focus`, `task`, `depth`, `lvl`, `mod`, `f`, `fld` | title, narrative, work context, task, scope, levels, modality, family, primary field | same columns |
| `disc`, `ft` | discipline group (Cross-curricular → `interdisciplinary`) | same |
| `cap` | kind of AI + secondary (institutional → text chat, discipline-specific → code) | same; "no AI" kind → `none_required` only where no AI output is used, otherwise `text_chat` (the instructor prepares it) |
| `ar`, `hm` | reviewed controlled values | assigned from the free-text role and move |
| `gate` | human move detail | written from the narrative (≤ 45 words) |
| `ac`, `icap`, `sc` | assigned from the narrative | assigned from the narrative |
| `sen`, `pc`, `dis`, `eq` | assigned from the narrative and the reviewed participation claims; remix `eq` = equipment | same; `eq` from the access note |
| `st` | `not_specified` (grading is left to faculty) | same |
| `pol` | `instructor_side` unless students do it; otherwise the most restrictive compatible position | same |
| `dl`, `risk`, `na` | what is produced, access note, non-AI route | what is produced, access note (no non-AI route column) |
| `dep`, `chk` | depends on the AI for, checked against | same columns |
| `cit`, `attr` | every APA 7 citation; every CC attribution | same columns |
| `lic`, `licu`, `licn` | CC BY-NC-SA 4.0 (the collection's license) with a note on what the adapted sources require | same |
| `rel` | parent activity's source (existing CSR), operation source, theory chapter, companion | every relation in the provenance sheet |
| `par` | the published activity it builds on | — |

Assigned values were read from each record by reviewers working to written definitions.
A value the record does not establish is `not_specified`, so the Finder treats it as
unknown and never as a confirmed absence.

## 4. Licenses

Every set record carries the collection's CC BY-NC-SA 4.0 license, and `licn` says why:
attribution-only sources, a NonCommercial source, a CC BY-NC-SA source, or (Original
Synthesis) no adapted wording or structure. Every adapted source keeps its own license and
attribution. The stage refuses an `Adapted from` relation to a NoDerivatives work; the three
NoDerivatives books are cited for ideas only. Not legal advice: the 31 published activities
that adapt CC BY-SA sources (27 under 4.0, three under 3.0 IGO, one under 3.0) still sit under
the CC BY-NC-SA 4.0 footer, a question this stage does not settle.

## 5. Sources

331 new source records (`SRC-0001`…`SRC-0331`) and 75 existing ones extended. A source is
reused when its DOI or link matches an existing record; all 92 remix parents resolve to the
source record of the published activity they adapt. The `SRC-` ids are site-side. When the
pipeline's canonical source register mints CSR ids for these works, a crosswalk should
replace them.

## 6. Contract

The stage adds public fields `tier`, `par`, `dep`, `chk` and the top-level `tiers` sections.
They exist only in the site's staged output, so the export contract stays 1 and
`check_release.py` is unchanged. When the pipeline exports the sets itself, these fields
should move into the export, with `contract` raised to 2 in the export and in
`check_release.py` together.

## 7. Checks

- `tests/tiers_test.py`: the licensed collection is byte-for-byte unchanged; every set record
  is labeled and traceable; held records stay out; types without capability keys count their
  records; twelve unreviewed or unsafe changes are refused; nothing NoDerivatives is adapted;
  input and output are pinned.
- `tests/data-integration.test.js`: all 303 set records carry their set, full provenance and
  sources that link back; every remix names a published parent and a theory relation; each
  record has a zero-mismatch Finder path (1,588 combinations).
- `tests/pages.test.js`, `tests/site.test.js`, `tests/a11y.test.js` (three new states),
  `tests/matching.test.js` (set records follow reported ones at equal score): all pass with
  the rest of `npm test`.

## 8. Decisions left open

1. **How the sets were drafted.** The public pages say the sets were written for the
   collection and not yet tried. They do not say how they were drafted or reviewed. Whether
   to state that, and in what words, is open.
2. **"No AI" and instructor-prepared output.** Settled by the AI-use review
   ([AI-USE-2026-10-05.md](AI-USE-2026-10-05.md)). Every record now carries `op`, and the
   renamed limit admits activities in which only the instructor operates a tool, including
   these synthesis records.
3. **Rank.** `gr: 0` places set records after reported activities at equal match. Raising it
   is a one-line change in the manifest and in `tools/tiers.py`.
4. **Pipeline import** of the sets and their sources (section 6).
