# Curation, 2026-09-29

`content/curation.json` is the fourth and last data stage. It runs after the serial-comma
review (`tools/curation.py`), pins its input and output hashes like the earlier stages, and
leaves the imported release in `data/` untouched. Every operation carries its reason and
evidence in the manifest. Result: **779 activities / 309 sources** in both tools.

## 1. Withdrawn: activities What If AI could never show (36)

The Finder admits only the constructive, interactive, not-applicable, and under-review
engagement classes (`admitted()` in `src/js/matching.js`). Thirty-five activities recorded
as `active` and one as `passive` were published in The Register but could never appear in
What If AI, whatever a reader answered. They are withdrawn from both tools. Six sources
that supported only those activities are removed from The Register (CSR-0102, CSR-0229,
CSR-0307, CSR-0311, CSR-0360, CSR-0371). The imported release keeps every record.

The stage now **refuses to build** if any published activity fails the Finder's admission
rule, so a future release cannot reintroduce Register-only activities without a review.
Links to a withdrawn activity show "That activity is not in the published collection" in
both tools, and saved lists already label such an entry as no longer in the collection.

## 3. Provenance class `prompt_specification` retired

The class did not affect matching or results; it only chose a caution note and a label.
It was also outside the controlled vocabulary (`original_synthesis`, `licensed_adaptation`,
`hybrid_synthesis`, `source_uncertain`). The 115 records adapt openly licensed published
prompts or workflows, so they are **Licensed Adaptations**, and the class description now
says "activity, prompt, or workflow".

The fact the old class carried, that no one has reported using the design, is kept as its
own field, `use: "unreported"`. Each of these activities still shows "A published prompt or
workflow … no results from using it have been reported". Evidence of use is also one of
the result-order tie-breaks (see [MATCHING.md](MATCHING.md)).

## 4. Result order

Groups were ordered by match score, then the corpus quality tier, then **array position**.
Array position follows import batches, so equally good records from later batches were
always last, and one batch could fill the first page. Ties are now broken by quality first
(score, then quality tier, then reported use) and finally by a fixed hash of the
identifier, which favors no batch, source, or letter. Source diversity is not enforced: if
the best matches share a source, they stay on top. `tests/matching.test.js` checks that
reversing or shuffling the activities never changes any ordered group.

## 5. Spelling

American English in editorial prose: *recognized*, *skepticism* (×2), *analyzes* (a verb),
and *acknowledgment* in a policy rule, plus one code comment. Left as written: proper
names (Teaching and Learning Centre, Professor in Counselling, Open Government Licence,
ERC Work Programme), titles of works (AI, Humour and Genre Writing), source terms
(summarisation), quotations, section names in locators, standard terms (grey literature),
and matching codes (`informal_acknowledgement`).

## 6. Publication review no longer published

The site used to publish `content/publication-review.json`, which includes the 11 held
additions' titles and internal review notes. It now stays in the repository; `version.json`
keeps only its revision and counts. The curation manifest is likewise not published. The
repository itself is public, so `data/` and `content/` remain readable there.

## 7. Links that cannot be decoded

A link with a broken `%` escape (for example, one cut off by an email client) threw an
error and left the page blank below the header. Both tools now treat an undecodable part as
unrecognized: the Finder returns to the first question, and an activity link reports that
the activity is not in the published collection. The Finder now shows that note for any
unknown activity link, as The Register already did. `tests/curation-browser.test.js`
covers these cases.

Integration review also checks navigation from an open activity to a malformed or
withdrawn link. The Register now closes the stale dialog and clears the missing-activity
notice when a valid activity is opened, matching the Finder's recovery behavior.
